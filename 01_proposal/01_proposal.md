# 1차 과제 — 데이터분석 프로젝트 기획

## 프로젝트 제목

**온라인 소매 거래 데이터로 살펴보는 주문·매출 패턴 분석**

## 1. 프로젝트 배경 및 목적

온라인 소매에서는 상품, 주문 시점, 고객이 거주하는 국가에 따라 주문과 매출의 모습이 다를 수 있다. 이런 패턴을 살펴보면 어떤 상품이 많이 판매되는지, 주문이 집중되는 시기는 언제인지 파악하는 데 도움이 된다.

본 프로젝트에서는 공개된 실제 거래 데이터를 이용해 주문과 매출의 시간별·상품별·국가별 분포를 탐색한다. 분석 결과를 바탕으로 관찰된 패턴을 데이터에 근거해 설명하고, 데이터의 범위와 한계도 함께 정리하는 것을 목적으로 한다. 한 기업의 과거 자료를 분석하므로 전체 온라인 소매 시장에 그대로 일반화하거나 원인과 결과를 단정하지 않는다.

## 2. 해결하고 싶은 문제

주문이 특정 시기, 상품, 국가에 집중되는지 알기 어렵다면 판매 현황을 이해하고 재고나 판촉 계획을 세우기 어렵다. 이 프로젝트는 거래 내역을 요약해 다음과 같은 질문에 답하고자 한다.

- 매출액과 주문 건수는 월별로 어떤 변화를 보이는가?
- 요일과 시간대에 따라 주문 건수 또는 매출액이 다른가?
- 상품 및 고객 거주 국가별 매출 구성에는 어떤 차이가 있는가?

분석은 해당 공개 데이터에서 확인할 수 있는 과거 패턴을 설명하는 데 활용한다. 실제 기업의 재고·판촉 의사결정에 직접 적용하려면 최신 자료와 추가 정보가 필요하다.

## 3. 핵심 분석 질문

1. 분석 기간의 월별 주문 건수와 거래 금액은 어떻게 변하는가?
2. 요일과 시간대별 주문 건수 및 거래 금액에 차이가 있는가?
3. 상품과 고객 거주 국가별 거래 금액의 분포 및 기여도는 어떻게 다른가?

질문별로 집계 단위와 지표를 명확히 정한 뒤 분석한다. 거래 금액은 우선 `Quantity × UnitPrice`로 계산하되, 취소 주문이나 음수 수량이 합계에 미치는 영향을 별도로 확인하고 처리 기준을 보고서에 기록한다.

## 4. 데이터 확보 계획

- **데이터명:** Online Retail
- **출처:** [UCI Machine Learning Repository — Online Retail](https://archive.ics.uci.edu/dataset/352/online+retail)
- **수집 방법:** UCI 페이지에서 `Online Retail.xlsx` 파일을 내려받는다. 필요하면 UCI가 안내하는 `ucimlrepo` 패키지로도 불러올 수 있다.
- **확보 가능 여부:** 공개 다운로드가 가능하며, 본 기획 시점에 데이터 설명과 파일 페이지를 확인했다.
- **예상 규모:** UCI 안내 기준 거래 행 541,909건, 2010년 12월 1일부터 2011년 12월 9일까지의 자료, 파일 크기 약 22.6MB이다.
- **이용 조건 및 출처 표기:** UCI 페이지에 표시된 CC BY 4.0 조건에 따라 출처를 표기한다. 인용 정보는 D. Chen (2015), *Online Retail*, UCI Machine Learning Repository, DOI: [10.24432/C5BW33](https://doi.org/10.24432/C5BW33)이다.

## 5. 예상 데이터 구조

각 행은 거래에 포함된 상품 항목을 나타내는 거래 명세 단위로 예상한다. UCI가 안내한 주요 변수는 다음과 같다.

| 변수 | 의미 | 활용 계획 |
|---|---|---|
| `InvoiceNo` | 거래 번호. `C`로 시작하면 취소 거래를 나타냄 | 주문 단위 집계 및 취소 거래 확인 |
| `StockCode` | 상품 코드 | 상품별 집계 |
| `Description` | 상품명 | 상품 코드 확인 및 요약 |
| `Quantity` | 거래된 상품 수량 | 수량 및 거래 금액 계산 |
| `InvoiceDate` | 거래 발생 날짜와 시각 | 연·월·요일·시간대별 분석 |
| `UnitPrice` | 상품 단가(파운드) | 거래 금액 계산 |
| `CustomerID` | 고객 식별 번호 | 필요 시 고객별 요약; 결측 및 식별 범위 확인 |
| `Country` | 고객 거주 국가 | 국가별 비교 |

실제 파일을 확보한 뒤 행·열 수, 자료형, 결측치, 중복, 취소 거래, 수량·가격의 음수 또는 0 여부를 확인한다. UCI 설명과 실제 파일의 값이 다른 경우 실제 확인 결과와 처리 기준을 우선 기록한다.

## 6. 예상 분석 방법

1. 원본 파일과 변수 설명을 확인하고 분석에 필요한 자료형으로 변환한다.
2. 결측치, 중복, 취소 거래, 비정상 수량·가격을 확인하고, 기준을 문서화해 전처리한다.
3. 주문 건수와 거래 금액의 기술통계를 계산하고 월·요일·시간대·상품·국가별로 집계한다.
4. 선그래프, 막대그래프, 분포 그래프 등으로 주요 패턴을 시각화한다.
5. 취소 거래 포함 여부 등 합리적인 기준을 달리했을 때 주요 결과가 얼마나 달라지는지 확인한다.

기획 단계에서는 설명 가능한 집계와 시각화를 중심으로 한다. 데이터 구조와 피드백을 확인한 뒤 필요할 때만 추가 분석 방법을 선택한다.

## 7. 생성형 AI 활용 및 검증 계획

생성형 AI는 분석 질문 다듬기, pandas 전처리·집계 코드 초안, 시각화 코드, 오류 해결, 해석 문장 점검에 활용한다. AI가 만든 결과를 그대로 확정하지 않고 다음을 확인한다.

- 코드 실행 후 행 수, 합계, 결측치와 취소 거래 건수를 원자료와 대조한다.
- 집계 기준과 계산식을 확인하고, 일부 표본을 직접 계산해 결과를 점검한다.
- 그래프와 수치가 실제 실행 결과를 반영하는지 확인한다.
- 관찰한 사실과 가능한 해석을 구분하고, 데이터만으로 입증되지 않은 인과관계는 주장하지 않는다.
- AI 활용 내용, 수정 사항, 검증 방법을 각 단계의 기록에 남긴다.

## 8. 향후 프로젝트 진행 계획

1. **1차 — 기획:** 주제, 분석 질문, 데이터 출처, 예상 분석 방법을 정리한다.
2. **2차 — 데이터 확보·전처리·EDA:** 원본 데이터를 확보하고 품질을 확인한 뒤 전처리 기준과 주요 시각화를 기록한다.
3. **3차 — 분석·검증:** 질문에 맞는 비교와 분석을 수행하고, 지표·기준 변경에 따른 결과를 점검한다.
4. **4차 — 최종 결과물:** 분석 근거, 핵심 인사이트, 한계, AI 활용 및 검증 과정을 정리해 보고서와 발표 자료를 완성한다.

## 9. 예상 한계

- 데이터는 한 영국 온라인 소매업체의 2010~2011년 거래이므로 현재 시장이나 다른 기업의 특성을 대표하지 않는다.
- 고객·상품·마케팅 상황에 대한 정보가 제한되어 매출 차이의 원인을 단정할 수 없다.
- 취소 거래와 음수 수량 등의 처리 방법에 따라 집계 금액이 달라질 수 있으므로 기준별 결과를 구분해 해석한다.
- `CustomerID` 등 실제 데이터 품질은 파일을 내려받은 뒤 다시 확인한다.
